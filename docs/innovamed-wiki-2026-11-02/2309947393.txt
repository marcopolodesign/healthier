# Generar Práctica (v27, 2026-06-12)
 
 Versión de documentación: v5
 Fecha de modificación: 12/06/2026
 Información general
 URL del endpoint
 POST {{baseUrl}}/apirecipe/prescribirPractica
 Formato: JSON
 Autenticación: Requerida (Bearer Token)
 Este Endpoint requiere Autenticación , por lo que se debe enviar un token válido en los Headers para autorizar las solicitudes.
 Descripción funcional
 El servicio Generar Práctica permite la creación de prescripciones electrónicas de estudios/prácticas médicas.
 A través de este endpoint se registra una prescripción asociando:
 Paciente
 Médico
 Prácticas solicitadas
 Información de cobertura (si aplica)
 Datos del lugar de atención
 Configuraciones adicionales como posdatado o información extra
 Como resultado, el sistema genera una prescripción electrónica válida, con su PDF asociado, que puede ser:
 Consultado
 Validado
 Descargado
 Auditada de forma trazable
 Flujo general del proceso
 El integrador envía los datos del paciente, médico y prácticas.
 El sistema valida:
 Datos obligatorios
 Reglas por financiador (si hay cobertura)
 Reglas de negocio y formatos
 Se genera la prescripción electrónica.
 Se retorna:
 Información de la receta
 Links de descarga y verificación del PDF
 Datos consolidados de la prescripción

 Notas Técnicas
 Solicitud:
 Objeto Cobertura : 
 Los parámetros se consideran opcionales cuando el paciente no tiene cobertura al momento de prescribir. Cuando se da el caso de que se utilizará su cobertura para prescribir y hay que indicar los datos de la misma, los parámetros dentro de este objeto se considerarán obligatorios .
 El parámetro dniTitular sólo es utilizado por algunas entidades. Si no lo precisa, no es obligatorio enviarlo.
 Se disponibilizan dos parámetros para poder indicar información del plan del afiliado: planId y plan . El primero corresponde al identificador del plan y el segundo al nombre o código de plan que se utiliza, por ejemplo, Ambulatorio, PMI, Diabetes, etc.
 Se realizan validaciones sobre ambos campos (si son informados) y se toma como mandatorio el planId . Si éste llegase a ser incorrecto, se valida el plan y si está ok, el flujo de prescripción continúa correctamente, sino se rechaza. 
 NOTA : este comportamiento no se utiliza para todas las entidades integradas.
 Objeto Medico: 
 La profesión es prioritaria por sobre la especialidad . Dado el caso en que se informe una especialidad y la profesión se deje vacía, el sistema asignará por defecto la profesión “Médico”.
 Sub objeto Sello: 
 El sello se compone por 3 líneas, en las cuales se puede plasmar la información que el profesional precise. Se sugiere que entre los datos que se ingresen sean el nombre, apellido, especialidad, matrícula y contacto del profesional que prescribe.
 Dado el caso donde no se envíe información en ninguno de estos parámetros, por defecto se asignarán los siguientes datos para ser mostrados en el PDF:
 Nombre del profesional
 Profesión
 Tipo y número de matrícula
 Si el sello llega vacío (todas las líneas vacías), se omite. Si alguna línea tiene contenido, se validan los límites por línea y, si se exceden, se rechaza la solicitud con el código de error correspondiente.
 Firmas y logos 
Firma del médico y logos pueden venir por URL o base64 . Si alguna imagen no puede obtenerse o es inválida, se omite y la emisión continúa (se registra en logs).
 Objeto Prescripción :
 El parámetro nombre es de texto libre y puede ingresarse el nombre o descripción de la práctica que se requiere prescribir. Ese texto se visualizará en el PDF.
 Nota sobre el funcionamiento de ID y nombre :
 Si se ingresa el ID de la práctica, se validará con la DB y tomará desde allí la información de la práctica para la generación del PDF.
 Si No se ingresa el ID y se ingresa el nombre por texto libre, éste texto matchea con el nombre de la práctica en la DB:
 Si el texto NO coincide con el de la DB, el servicio devuelve error.
 Si el texto SI coincide, la validación pasa correctamente.
 Si se ingresa el ID y al mismo tiempo se ingresa el nombre de una práctica distinta al ID indicado, se tomará como mandatario el ID .
 El parámetro codigo hace referencia a un código propio de la práctica que se quiere prescribir. Este dato actualmente no se consulta ni se valida sobre nomencladores específicos.
 Para el parámetro codigodiagnostico , existe una validación donde, si el código CIE-10 que se utiliza está relacionado a ETS, HIV o similares, se realiza la ofuscación de datos del paciente en el PDF para proteger su identidad. A su vez, también se oculta la descripción del diagnóstico y sólo se visualizará el código CIE-10.
 Normalizaciones y mínimos en ítems 
 cantidad : si se envía menor a 1, se fuerza a 1 .
 observaciones : se limpia null a cadena vacía y se trunca a 200 caracteres.
 nombre / código / categoría de la práctica: se truncan a 200 caracteres.
 Campos del médico Especialidad y Profesión : se truncan a 80 caracteres.
 Diagnóstico e impresión 
 El parámetro diagnostico que corresponde al diagnóstico general posee dos comportamientos en base a la información que se ingrese:
 Se puede ingresar texto libre, por ej. “Resfriado leve”, y ese texto será el que se muestre en el PDF.
 Se puede ingresar un código CIE-10, por ej. “M255”, y el campo validará que se trata de un código CIE-10, por lo que en el PDF se visualizará el código y la descripción del diagnóstico que le corresponda. En el caso del ejemplo será “M25.5 - DOLOR EN ARTICULACIÓN”.
 Si se ingresa como diagnóstico general un código CIE-10, y éste está relacionado a ETS, HIV o similares, se realiza la ofuscación de datos del paciente en el PDF para proteger su identidad. A su vez, también se oculta la descripción del diagnóstico y sólo se visualizará el código CIE-10.
 El parámetro imprimirDiagnostico se utiliza para indicar si se desean visualizar los diagnósticos o no en la prescripción. 
 Puede recibir los valores “S”, “N” o ““ (vacío).
 Al enviar “S”, se mostrarán en el PDF todos los diagnósticos establecidos.
 Al enviar “N”, no se mostrará en el PDF ningún diagnóstico establecido.
 Al enviar ““, se tomará como “S” y se mostrarán en el PDF todos los diagnósticos establecidos.
 Si se envía cualquier otro valor, el sistema devolverá error.

Por ejemplo, si asigno como fechaEmision el día 10/01/2025 , y en la fecha de posdatada también ingreso la fecha 10/01/2025 , se devolverá un error indicando que “ LA FECHA DE POSDATADO DEBE SER SUPERIOR A HOY ".

 Preguntas Frecuentes
 ¿Cómo funciona el split de prescripciones? 
 En los casos donde una solicitud genera más de una receta o práctica, por ejemplo, cuando se aplica un split por recetas posdatadas, por criterios de medicamentos, por planes del financiador u otras reglas de negocio, cada documento del lote se procesa de forma independiente y todos quedan agrupados bajo un mismo identificador de transacción ( idTransaccion ). Esto significa que, si alguno de los documentos no puede generarse por algún motivo, el resto se genera igualmente de forma correcta. En esa situación, la respuesta del servicio devuelve un estado 200 e informa el resultado en un único cuerpo de respuesta: las recetas o prácticas generadas con éxito viajan en la lista recetas , mientras que el detalle de las que no pudieron generarse viaja en la lista errores , donde cada entrada indica el tipo de error ( error ), una descripción del mismo ( mensaje ) y los medicamentos asociados ( medicamento ) que permiten identificar qué ítem falló. De este modo, ante un resultado parcial, el cliente recibe en una misma respuesta tanto los documentos generados correctamente como la información de los que fallaron, por lo que es importante revisar siempre el contenido de la respuesta, en particular la lista errores , y no únicamente el código de estado HTTP.
 ¿Cómo hago para posdatar una prescripción? 
 Si necesitas emitir prescripciones con fechas futuras, puedes hacerlo utilizando la funcionalidad de prescripciones posdatadas con el objeto recetasPostadatas . Este proceso permite que, además de la prescripción principal que estás generando, el sistema cree prescripciones adicionales con fechas específicas o con un intervalo definido.
 Cuando se desea posdatar prescripciones con fechas exactas, puedes indicar las fechas en el formato correcto (DD/MM/AAAA). Por ejemplo, si defines que las prescripciones se generen los días 15/01/2025 , 15/02/2025 , y 15/03/2025 , esas serán las fechas que se utilizarán. En este caso, el sistema ignorará otros parámetros como la cantidad de prescripciones o los días a posdatar.
 Si lo que necesita es emitir sólo una receta con una fecha posterior a la actual, se deberá utilizar el parámetro fechaEmision indicando la fecha requerida.
 En resumen, esta funcionalidad te permite planificar prescripciones futuras según las necesidades del paciente, asegurando que estén listas y disponibles en las fechas definidas.
 ¿Por qué me falla después de las 21hs? 
 Esto suele ocurrir porque la fecha de emisión de la prescripción se indica en un formato incorrecto o sin considerar que debe enviarse en el formato UTC (Tiempo Universal Coordinado). UTC es un estándar internacional de tiempo que puede diferir de tu hora local.
 Por ejemplo:
 Si se está en Argentina, la zona horaria suele ser UTC-3 (UTC menos 3 horas). Esto significa que cuando en el reloj son las 21:00, en UTC ya es medianoche del día siguiente.
 Si se ingresa mal la hora sin ajustar al formato UTC, el sistema podría interpretar que la fecha está fuera del rango permitido o en un día incorrecto, generando el error.
 Cómo evitar errores: 
Cuando se envíe la fecha de emisión, se debe utilizar el formato UTC completo. Por ejemplo:
 Correcto: 2025-01-03T23:00:00Z (23:00 en UTC).
 Incorrecto: 2025-01-03 23:00 (sin especificar el formato de zona horaria).
 Por ejemplo, la fecha y hora "2024-07-10T02:26:08Z" está en formato UTC (Tiempo Universal Coordinado).
 Para convertirla a una hora local:
 En Argentina, la diferencia horaria suele ser UTC-3.
 Esto significa que se deben restar 3 horas de UTC para obtener la hora local:
 UTC: 2024-07-10 a las 02:26:08.
 Hora en Argentina (UTC-3): 2024-07-09 a las 23:26:08 (11:26:08 PM del día anterior).
 Se puede utilizar la siguiente web para visualizar la hora UTC o Z time: https://www.utctime.net/z-time-now
