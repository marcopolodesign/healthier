El profesional accede vía browser en su teléfono. La ruta /profesional/emergencias es una página standalone — sin sidebar, sin AppLayout. Usa Supabase Realtime para recibir notificaciones instantáneas.

5. TODOs y gaps conocidos

📱 Resume path — app cerrada: Si el paciente cierra la app con una emergencia activa (status = dispatched/in_transit), no hay mecanismo automático para volver al mapa. Fix: al cargar el home, llamar a EmergencyService.getActiveByPatient(userId); si existe, mostrar banner rojo "Emergencia activa" → /emergency/map?triageCode=X.
💬 WhatsApp al profesional: La subscripción Realtime solo funciona si el browser está abierto. Cuando llega una emergencia, enviar un mensaje WhatsApp con deeplink /profesional/emergencias?id=UUID. Stack: Supabase Edge Function en ON INSERT emergencies → Twilio/Meta Cloud API → professional.phone.
💳 Pago real: El pago sigue siendo un mock (setTimeout 1500ms). Integrar Mercado Pago o Stripe. El comprobante debe generarse al confirmar el pago, no al crear la emergencia.
📍 ETA real: El countdown es simulado (4 min). Integrar Google Routes API o similar para calcular ETA real desde las coordenadas del profesional hasta las del paciente, y actualizarlo en tiempo real.
🔔 Push notifications (mobile): Cuando la emergencia cambia a arrived o completed, el paciente debería recibir una push notification incluso con la app cerrada. Stack: Expo Notifications + Supabase Edge Function.
