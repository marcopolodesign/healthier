🗣 Terminología — el mismo concepto, dos nombres

Healthier dice Heural dice Estándar subyacente Notas
Paciente Patient FHIR Patient En GraphQL: patientId. En FHIR: /fhir/Patient/:id
Profesional / Médico Practitioner FHIR Practitioner practitionerId. Requiere active: true para crear turnos.
Institución (Healthier como plataforma) Institution FHIR Organization ID fijo: E03967DE46751D21E698238E90810459. Va en header x-institution-id.
Turno / Cita Appointment FHIR Appointment appointmentId. Crear un appointment genera un Encounter automáticamente.
Consulta médica (la sesión clínica) Encounter FHIR Encounter encounterId. Se crea junto con el Appointment. Almacenamos en consultations.heural_encounter_id.
Pre-consulta (formulario previo) PatientPreconsulta — Custom de Heural. El paciente envía antes de la consulta. Campo principal: reason.
Diagnóstico Condition FHIR Condition Código SNOMED o ICD-10. Ver FHIR /fhir/Condition.
Receta MedicationRequest FHIR MedicationRequest medicationRequestId. Se comparte por WhatsApp o email. ID del meds = SNOMED conceptId string.
Medicamento (búsqueda) SNOMED concept SNOMED CT GET /hermes/v1/snomed/search?s=. Devuelve conceptId (string). Ej: "387207008" = ibuprofeno.
Signo vital / Observación Observation FHIR Observation observationId. Category: VITAL_SIGNS. Valor va en value.quantity.{value, unit}.
Alergia AllergyIntolerance FHIR AllergyIntolerance allergyIntoleranceId. Category: MEDICATION | FOOD | ENVIRONMENT | BIOLOGIC.
Historia clínica Patient Summary IPS (FHIR) GET /fhir/Patient/:id/$summary. Bundle FHIR con toda la historia.
Vacuna Immunization FHIR Immunization GraphQL: immunizations query, saveImmunization mutation.
Ant. familiares FamilyMemberHistory FHIR FamilyMemberHistory GraphQL: familyMemberHistory query, createFamilyMemberHistory mutation.
Obra social / seguro Insurance / Coverage FHIR Coverage GET /public/search-insurances (sin auth).
Informe / Estudio DiagnosticReport FHIR DiagnosticReport GET /fhir/DiagnosticReport?patient=:id. Soporta OCR para PDFs.
Transcripción de audio Whisper transcription — 3 endpoints: upload, transcribe, upload-and-transcribe. ⚠️ 404 en UAT.
Usuario del sistema User (userId) — En login responde userId. Diferente de patientId / practitionerId de FHIR.
Membresía en institución InstitutionMembership — membershipId. Roles: PATIENT, PRACTITIONER, OWNER, etc. El header x-institution-id activa el contexto de institución.

🔒 Auth

Healthier — Supabase Auth

Login
supabase.auth.signInWithPassword()
Token
JWT en localStorage, Supabase lo rota solo
Header
Authorization: Bearer <token>
Roles
patient / professional / admin / super_admin
RLS
Políticas en cada tabla, función get_my_role()

Heural

Login
POST /auth/login → recibe token + refreshToken
Header GQL
jwt: <token> (preferido) o Authorization: Bearer
Header FHIR
jwt: <token> ÚNICAMENTE
Header extra
x-institution-id: <institutionId> ← OBLIGATORIO en GQL + SNOMED
Refresh
POST /auth/token — token rotation (el viejo expira)
Expiración
JWT: largo (hasta 2027). RefreshToken: corto (~7 días).

Headers por tipo de request

Tipo Headers requeridos Notas
POST /graphql jwt: <token> + x-institution-id: <id> + Content-Type: application/json Sin x-institution-id → UNAUTHORIZED aunque el JWT sea válido
GET /hermes/v1/snomed/search Authorization: Bearer <token> + x-institution-id: <id> Búsqueda de medicamentos / SNOMED
GET /fhir/... jwt: <token> No acepta Authorization: Bearer. Solo lectura.
/public/..., /fhir/metadata — Sin auth

🔄 Flujo de consulta end-to-end

Paciente reserva turno

HealthierElige profesional en marketplace
→
HeuralcreateAppointment()
→
SupabaseGuardar heural_appointment_id + heural_encounter_id en consultations
→
HeuralconfirmAppointmentAttendance()

Pre-consulta (paciente)

HealthierPreconsultaForm.jsx — paciente completa motivo
→
HeuralsubmitPatientPreconsultaV2(appointmentId, {reason})
→
HeuralProfesional lee con encounterPreconsulta()

Consulta clínica (profesional)

HeuralLee pre-consulta + alergias + vitales previos
→
HeuralRegistra vitales con createObservation()
→
HeuralBusca medicamento en SNOMED (searchMedication())
→
HeuralCrea receta con createMedicationRequest()
→
HeuralEnvía por WA sharePrescriptionByWhatsApp()
→
HeuralCierra encounter con updateEncounter({status: FINISHED})
→
SupabaseActualiza consultations.status = completed

🚩 Flags abiertos — pendientes con Heural

Contacto: maguirre@heural.com

1
createUser → active: false en FHIR

Todos los usuarios creados via createUser quedan active: false en el FHIR Practitioner. Esto hace fallar createAppointment con INVALID_PRACTITIONER. Bloqueante para el flujo principal.

2
createPractitioner requiere campo discipline no documentado

La mutation falla sin el campo discipline pero no está en los docs. Necesitamos saber el tipo/enum.

3
userByEmail → INSUFFICIENT_PRIVILEGES

Con token de plataforma (rol USER), la query userByEmail devuelve error. Solo funciona con token de admin/owner. Limita la búsqueda de usuarios por email desde el server.

4
role → roles (array) en institutionMemberships

Los docs dicen role pero el schema real usa roles (array). Documentado, workaround aplicado.

5
Audio transcription 404 en UAT

Los 3 endpoints de Whisper (POST /audio/upload, /audio/transcribe, /audio/upload-and-transcribe) devuelven 404. No disponibles en el entorno UAT.

6
doctorClinicalChat — ANTHROPIC_API_KEY no configurada

El chat clínico IA devuelve error de API key. No usable en UAT.
