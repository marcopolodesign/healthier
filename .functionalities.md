## Visión general

**Healthier** es un marketplace de salud digital para Buenos Aires que conecta pacientes con profesionales de salud verificados. Incluye historia clínica digital, recetas electrónicas, IA de salud, análisis de laboratorio con OCR, pagos online y gestión completa de la práctica para profesionales.

## Funcionalidades para pacientes

### Búsqueda y reserva
- **Buscar profesionales** (`/paciente/buscar`) — filtros por especialidad, disponibilidad, precio, modalidad (online/presencial)
- **Reservar consulta** (`/paciente/reservar`) — wizard multi-step: especialidad → profesional → horario → pago
- **Buscar profesional** (`/paciente/buscar-profesional`) — búsqueda avanzada con mapa
- **Perfil público del profesional** (`/paciente/profesional/:id`) — bio, rating, reseñas, precio, especialidad, Calendly embed
- **Turno confirmado** (`/paciente/turno-confirmado/:id`) — confirmación post-reserva con deeplink a Google Calendar

### Consultas y videollamadas
- **Sala de espera** (`/paciente/sala-espera/:consultationId`) — Supabase Realtime Presence, timer 5 min no-show
- **Videollamada** (`/paciente/videollamada/:id`) — Daily.co createCallObject(), UI full-ownership: VideoTile local/remote, cámara/micrófono, PiP
- **On-demand / Urgente** (`/paciente/ondemand/:vertical`) — consulta inmediata, busca profesional disponible al instante
- **SOS / Emergencias** (`/paciente/sos`) — flujo de emergencia
- **Walk-in queue** (`/paciente/urgente`) — cola de consulta urgente con Realtime auto-navegación
- **Reseña y calificación** (`/paciente/consulta/review/:id`) — rating 1-5 + comentario post-consulta

### Historia clínica y documentos
- **Historia Clínica digital** (`/paciente/historia-clinica`) — timeline expandible por consulta: SOAP, condiciones, medicamentos, alergias; descargable con `window.print()` (Ley 26.529 Art. 15)
- **Documentos** (`/paciente/documentos`) — almacenamiento de docs médicos en Supabase Storage
- **Comprobantes** (`/paciente/comprobantes`) — recibos de pago agrupados por mes
- **Health Snapshot** (`/paciente/salud`) — resumen de salud: próximo turno, condiciones activas, medicamentos, alergias, stats

### Herramientas de salud
- **Biovisor** (`/paciente/biovisor`) — 3 tabs:
  - *Análisis*: OCR con Gemini sobre PDF/imagen de análisis de sangre
  - *Historial*: charts SVG con tendencias de parámetros y bandas de referencia
  - *Documentos*: lista de análisis guardados en DB
- **NutriPlan** (`/paciente/nutriplan`) — seguimiento de comidas + sugerencias de recetas con Gemini
- **Healthy IA** (`/paciente/ia`) — chat con IA (Claude Haiku) que usa historia clínica como system prompt para respuestas contextualizadas

### Pagos
- **Flujo de pago** (`/paciente/pago`) — MercadoPago Bricks, tarjeta tokenizada, `SavedCardSelector`
- **mp-save-card** — Edge Function: guarda/reutiliza tarjeta del paciente vía MP
- **mp-payment** — Edge Function: procesa el cobro y actualiza estado de consulta

### Perfil y configuración
- **Perfil paciente** (`/paciente/perfil`) — nombre, teléfono, dirección, tipo de sangre, obra social, contacto de emergencia
- **Onboarding paciente** (`/paciente/onboarding`) — flujo de creación de perfil al registrarse

## Funcionalidades para profesionales

### Dashboard y consultas
- **Dashboard profesional** (`/profesional/dashboard`) — próximas consultas, estado de verificación, notificaciones realtime de nuevos turnos, banner de conexión MP
- **Videollamada profesional** (`/profesional/videollamada/:id`) — mismo Daily.co, + panel clínico lateral
- **Panel clínico en videollamada** — escribe en Historia Clínica durante la consulta: notas SOAP, diagnósticos CIE-10, indicaciones, medicamentos, alergias, signos vitales (LOINC)
- **Detalle de consulta** (`/profesional/consultas/:id` vía `ConsultationDetail`) — resumen, prescripciones, archivos
- **Historial** (`/profesional/historial`) — lista de consultas pasadas con filtros

### Pacientes y clínica
- **Lista de pacientes** (`/profesional/pacientes`) — todos los pacientes atendidos
- **Historia clínica paciente** (`/profesional/historia-clinica/:patientId`) — vista completa de HC del paciente desde la perspectiva profesional
- **Perfil del paciente** (`/profesional/paciente/:id`) — datos del paciente

### Prescripciones
- **PrescriptionCreator** — UI completa para crear recetas con todos los campos RCTA:
  - Medicamento, concentración, presentación (23 opciones), vía (11 opciones), frecuencia, duración, cantidad
  - CIE-10 (diagnóstico), `is_chronic`, `priority`
  - Botón "Emitir receta electrónica (RCTA)" → Edge Function `rcta-issue` (Innovamed QBI2)
  - Estado: `pending` / `issued` / `error` + link al PDF

### Agenda y configuración
- **Agenda** (`/profesional/agenda`) — gestión de slots de disponibilidad, horarios por día
- **Configuración** (`/profesional/configuracion`) — Horarios, Tarifas, Cuenta en tabs
- **Ganancias** (`/profesional/ganancias`) — revenue tracking
- **Perfil profesional** (`/profesional/perfil`) — bio, foto, especialidad, matrícula (MN/MP), precio, Calendly URL
- **Onboarding profesional** (`/profesional/onboarding`) — 5 pasos: Especialidad → Presentación → Tarifas → Documentación → Revisión
- **NutriPlan Pro** (`/profesional/nutriplan`) — creación de planes nutricionales para pacientes

### Emergencias (mobile-first)
- **Emergencias** (`/profesional/emergencias`) — ruta standalone (sin AppLayout), UI full-screen para uso en campo: dispatch, navegación GPS, touch targets 56px

### IA
- **Alan IA companion** — panel deslizable en AppLayout con Claude Haiku: saludo contextual, quick actions, historial clínico del profesional

## Infraestructura y servicios externos

### Supabase
- **Auth** — JWT, roles via `profiles.role`
- **DB** — PostgreSQL con RLS por rol; `get_my_role()` SECURITY DEFINER para evitar recursión infinita
- **Storage** — `avatars` (public), `professional-docs` (private), `patient-docs` (private)
- **Realtime** — presencia en sala de espera, notificaciones de nuevos turnos en dashboard
- **Edge Functions** (Deno):
  - `daily-token` — genera token Daily.co para videollamada
  - `send-booking-email` — email de confirmación vía Resend (activo cuando `RESEND_API_KEY` configurado)
  - `send-push-notification` — Web Push a suscriptores
  - `appointment-reminders` — pg_cron cada 15min: recordatorio 1h antes
  - `appointment-reminders-24h` — recordatorio 24h antes
  - `mp-save-card`, `mp-payment`, `mp-connect`, `mp-webhook` — MercadoPago Marketplace
  - `rcta-issue` — receta electrónica vía Innovamed QBI2 (pendiente credenciales)
  - `sisa-verify` — verificación de matrícula vía SISA/Ministerio de Salud (pendiente credenciales)
  - `ai-companion` — proxy Claude Haiku para Alan IA

## Base de datos — tablas principales

| Tabla | Descripción |
|-------|-------------|
| `profiles` | Todos los usuarios (patient/professional/admin/super_admin), incluye DNI, UTMs, push_token |
| `professional_profiles` | Datos del profesional: especialidad, bio, precio, matrícula, SISA status, verificación |
| `consultations` | Consultas con estado (`pending`→`confirmed`→`in_progress`→`completed`/`cancelled`), precio, modalidad, Daily room URL |
| `availability_slots` | Slots de disponibilidad del profesional |
| `reviews` | Reseñas post-consulta (rating 1-5 + comentario) |
| `clinical_encounters` | Encuentros clínicos (one per consultation), modalidad, especialidad, licencia |
| `clinical_entries` | Notas SOAP append-only (tipo: Nota/Diagnóstico/Indicación/Addendum) |
| `clinical_conditions` | Condiciones ICD-10 del paciente |
| `clinical_allergies` | Alergias con severidad |
| `clinical_medications` | Medicamentos + campos RCTA completos (presentation, route, frequency, rcta_status) |
| `clinical_observations` | Observaciones LOINC (signos vitales, lab values) |
| `medical_documents` | Documentos del paciente (Storage URLs) |
| `diagnostic_reports` | Análisis de laboratorio con resultado OCR de Gemini |
| `emergencies` | Solicitudes de emergencia con estado y geolocalización |
| `walk_in_queue` | Cola de consultas urgentes con Realtime |
| `push_subscriptions` | Suscripciones Web Push por usuario |
| `payment_methods` | Tarjetas tokenizadas MP por paciente |
| `mp_accounts` | Cuentas MP conectadas por profesional |
